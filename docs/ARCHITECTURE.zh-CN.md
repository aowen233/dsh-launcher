# 架构

[English](ARCHITECTURE.md) | [简体中文](ARCHITECTURE.zh-CN.md)

## 组件

- `DshLauncher.Core`：与平台无关的版本、端口和脱敏策略。
- `DshLauncher`：原生 Windows 托盘应用及生命周期控制器。
- `launcher-status-plugin.mjs`：把任务状态写入用户私有本地文件的最小 DSH 插件。
- `dependencies.json`：经过审核的前置组件和可选插件清单。
- `installer`：按用户安装的 Inno Setup 安装包；仅在用户批准安装系统级 Node.js MSI 时单独请求 UAC。

## 启动流程

1. 获取当前用户互斥锁；后续实例通过仅限当前用户的命名管道发送命令。
2. 在不改动系统的情况下定位受支持的 Node.js。
3. 必要时下载固定版本的官方 Node.js LTS MSI，验证 SHA-256 后明确请求 UAC。
4. 每次操作只解析一次 `npm root --global`，并验证 DSH 包名、版本、入口及路径边界。
5. 只有进程命令行包含该全局 DSH 精确入口时才复用现有进程。
6. 否则选择回环端口、生成任务状态补丁，并用 `node.exe` 直接启动 DSH，不经过命令解释器。
7. 打开浏览器前确认监听地址仅为本机回环。

## 关闭代次

每次打开页面都会增加代次计数。浏览器断开后等待 12 秒，再以最新任务快照判断是否可以安全关闭。状态未知或过期时保持服务器运行。

有任务运行时，当前代次成为待关闭代次；重新打开页面会清除它。因此，在重新打开后完成的旧任务不能关闭新会话。

## 更新

后台检查不会中断启动，当前版本已是最新时不会显示对话框。用户批准更新后，只停止命令行再次验证为 npm 全局 DSH 的进程；其他 Node.js 程序不受影响。

未签名候选版只能作为标识清楚的 GitHub 预发布版公开。开源签名服务批准项目后，稳定版发布将使用受保护环境。
